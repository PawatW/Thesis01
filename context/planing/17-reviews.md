# Feature 17: Reviews — รีวิวจากผู้ใช้จริงที่รับของมาแล้วหลายรอบ

> เฟส: 4.5 | ฝั่ง: Buyer (เขียน) + ทุกคน (อ่าน) | สถานะ: **เสร็จแล้ว ยกเว้นแถวคะแนนในตารางเทียบ (Phase 7)** (2026-08-18) | Workflows: [W12](../workflows/w12-review.md)
> เพิ่ม 2026-07-25 — เดิมอยู่ใน Out of scope ของ [02](02-catalog.md) แต่ทำให้ objective "เปรียบเทียบข้ามแบรนด์" ไม่ครบ: ผู้ซื้อเทียบราคาได้ แต่เทียบ **คุณภาพ** ไม่ได้เลย

## จุดต่างที่ต้องเขียนในเล่ม

รีวิวใน e-commerce ทั่วไปมาจากการซื้อครั้งเดียว — คนรีวิวตอนเพิ่งแกะกล่อง ยังไม่รู้ว่าของดีจริงไหม
ที่นี่รีวิวผูกกับ **subscription** จึงบอกได้ว่า *"รีวิวโดยผู้ใช้ที่รับมาแล้ว 4 รอบ"* ซึ่งเป็นสัญญาณคุณภาพที่แพลตฟอร์มซื้อครั้งเดียวให้ไม่ได้ — และคนที่ **ยกเลิกไปแล้ว** ก็ยังรีวิวได้ (คนกลุ่มนี้แหละที่มีข้อมูลจริงที่สุด)

## ทำอะไรได้

- ผู้ซื้อให้ดาว 1-5 + คอมเมนต์ (ไม่บังคับ) **ได้ 1 รีวิวต่อ subscription** แก้ไขได้ภายหลัง
- เขียนได้เมื่อ **มีออเดอร์ที่ delivered/ยืนยันรับแล้วอย่างน้อย 1 รอบ** เท่านั้น (verified)
- ระบบบันทึก `cycles_received` ณ เวลาที่รีวิว → แสดง "รับมาแล้ว N รอบ" ข้างรีวิว
- แสดงคะแนนเฉลี่ย + จำนวนรีวิวบน: การ์ดสินค้า ([02](02-catalog.md)), หน้าสินค้า ([03](03-product-detail.md)), **ตารางเปรียบเทียบ ([04](04-compare.md))**
- ชื่อผู้รีวิวถูก mask (`ส****`) — รีวิวต้องไม่กลายเป็นช่องทางสืบว่าใครซื้ออะไร

## หน้าจอ & Routes

| Route | หน้าจอ |
|---|---|
| `(buyer)/subscriptions.tsx` | แถวรีวิวท้ายการ์ดแต่ละรายการ — ปุ่ม "ให้คะแนนสินค้านี้" / "แก้รีวิว ★N" หรือข้อความล็อกถ้ายังไม่เคยรับของ (ทำในหน้ารายการเลย ไม่ได้แยกหน้า `[id]`) |
| `(buyer)/product/[id].tsx` | ส่วนรีวิว: คะแนนเฉลี่ย + การกระจายดาว + รายการรีวิว (โหลดเพิ่มทีละ 10) |
| `(buyer)/compare.tsx` | เพิ่มแถว "คะแนน" ในตารางเทียบ |

## Components หลัก

- `RatingStars` — อ่านอย่างเดียว / แบบกดได้ (reuse ทั้งสองโหมด)
- `ReviewSheet` — เลือกดาว + คอมเมนต์ + ปุ่มบันทึก (ถ้าเคยรีวิวแล้วโหลดค่าเดิมมาแก้)
- `ReviewItem` — ดาว, คอมเมนต์, ป้าย **"รับมาแล้ว N รอบ"**, ชื่อ mask, วันที่
- `RatingSummary` — เฉลี่ย + จำนวน + แท่งการกระจาย 5→1 ดาว

## Data & Queries (API)

| Endpoint | ใช้ที่ |
|---|---|
| `POST /subscriptions/:id/review` | เขียน**และ**แก้ — รีวิวที่ 2 บนรายการเดิมคือการแก้ (upsert ด้วย `UNIQUE(subscription_id)`) |
| `GET /subscriptions/:id/review` | โหลดค่าเดิมมาใส่ในกล่องก่อนแก้ |
| `GET /subscriptions` | การ์ดพก `cyclesReceived` + `myRating` มาด้วย — หน้าจอจึงล็อกปุ่มได้ด้วยเงื่อนไขเดียวกับที่ API บังคับ โดยไม่ต้องยิงเพิ่มรายการละ 1 คำขอ |
| `GET /catalog/products/:id` | ส่วนรีวิวสาธารณะ: `rating`, `reviewCount`, `reviews[]` (ชื่อถูก mask แล้วที่ service) |

- **`cyclesReceived` ไม่มีใน DTO ขาเข้าโดยตั้งใจ** — นับจาก `orders.status = 'delivered'` ของ subscription นั้นทุกครั้งที่บันทึก ป้าย "รับมาแล้ว N รอบ" จึงเป็นข้อเท็จจริง ไม่ใช่คำประกาศของผู้รีวิว
- ยังไม่เคยมีออเดอร์ที่ `delivered` → API ตอบ 422 `NOTHING_RECEIVED_YET` (ปุ่มบนหน้าจอเป็นแค่ UX ชั้นสอง)
- response ของ catalog ไม่มี `buyerId` / `subscriptionId` เด็ดขาด — รีวิวต้องไม่กลายเป็นช่องทางสืบว่าใครซื้ออะไร ([security-design §4](../../docs/security-design.md))

## Validation & Edge cases

- ยังไม่เคยรับของ → ปุ่มรีวิว disabled + ข้อความ "รีวิวได้หลังได้รับสินค้ารอบแรก"
- subscription ที่ `cancelled` แล้ว → **ยังรีวิวได้** (ตั้งใจ — เขียนเหตุผลในเล่ม)
- แก้ไขรีวิว → `updated_at` เปลี่ยน + `cycles_received` อัปเดตเป็นค่าล่าสุด, UI แสดง "(แก้ไขแล้ว)"
- สินค้าถูกปิด/ร้านถูกระงับ → รีวิวเดิมยังอยู่ (ประวัติไม่หาย) แต่หน้าสินค้าเข้าไม่ได้
- สินค้าไม่มีรีวิว → แสดง "ยังไม่มีรีวิว" ไม่ใช่ 0.00 ดาว (กันเข้าใจผิดว่าคะแนนแย่)
- คอมเมนต์ ≤1000 ตัว (CHECK ที่ DB) — เว้นว่างได้ ให้ดาวอย่างเดียว
- ตารางเทียบ: สินค้าที่ยังไม่มีรีวิว แสดง "—" และไม่ร่วมไฮไลต์ค่าดีสุด

## Acceptance Criteria

- [x] subscribe → ยังไม่มีออเดอร์ delivered → รีวิวไม่ได้ — **TC-063** ตรวจทั้งปุ่มที่ถูกล็อกและการยิง API ตรง (422)
- [x] หลังได้รับของ → รีวิวได้ และป้ายแสดงจำนวนรอบจริง; แก้รีวิวแล้วจำนวนรอบถูกนับใหม่ (**TC-069** เทียบกับ `count(*)` ของออเดอร์ที่ delivered)
- [x] คะแนนเฉลี่ยบนการ์ด/หน้าสินค้า ตรงกับข้อมูลจริง (TC-016 เดิมของ catalog) · แถวคะแนนในตารางเทียบยกไป Phase 7 พร้อมหน้า compare
- [x] ชื่อผู้รีวิวถูก mask และ response ไม่มี `buyer_id`/`subscription_id` (e2e API)
- [x] รีวิว 2 ครั้งบน subscription เดียวกัน → กลายเป็นการแก้ไข ไม่ใช่รีวิวใหม่ (TC-069 ยืนยันว่ายังมีแถวเดียว)
- [x] ยกเลิก subscription แล้วยังรีวิวได้ (e2e API)
