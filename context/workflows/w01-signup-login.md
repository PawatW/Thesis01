# W01 — สมัครสมาชิก / ล็อกอิน / ตั้งค่าโปรไฟล์

> Actor: ผู้ใช้ใหม่/ผู้ใช้เดิม | Features: [01-auth](../planing/01-auth.md)

## Precondition
- ไม่มี (เป็น entry point ของระบบ)

## Trigger
- ผู้ใช้เปิดแอพครั้งแรก หรือ session หมดอายุ

## Main Flow A: สมัครสมาชิก

| # | ผู้กระทำ | การกระทำ | ระบบทำอะไร |
|---|---|---|---|
| 1 | ผู้ใช้ | เปิดแอพ → ยังไม่ล็อกอิน | root layout redirect ไป `(auth)/login` |
| 2 | ผู้ใช้ | กด "สมัครสมาชิก" กรอกชื่อ, อีเมล, รหัสผ่าน (≥8 ตัว) | validate ฝั่ง client |
| 3 | ระบบ | `POST /auth/register` | hash รหัสผ่านด้วย bcrypt (cost 12) → insert `users` → ออก access + refresh token ในทรานแซกชันเดียว |
| 4 | ระบบ | ได้ session กลับมา (ปิด email confirm ใน demo) | เก็บ session ใน AsyncStorage/localStorage |
| 5 | ระบบ | redirect เข้า `(buyer)/` หน้า catalog | — |

## Main Flow B: ล็อกอิน

| # | ผู้กระทำ | การกระทำ | ระบบทำอะไร |
|---|---|---|---|
| 1 | ผู้ใช้ | กรอกอีเมล + รหัสผ่าน → กด "เข้าสู่ระบบ" | `POST /auth/login` — เทียบ bcrypt เสมอแม้ไม่มีอีเมลนั้น (กัน timing attack) |
| 2 | ระบบ | ได้ session → โหลด `profiles` ของตัวเอง | select `profiles` where id = uid |
| 3 | ระบบ | เข้า `(buyer)/` (จำ session ไว้ เปิดแอพครั้งหน้าไม่ต้องล็อกอินใหม่) | — |

## Main Flow C: เพิ่มที่อยู่จัดส่ง

| # | ผู้กระทำ | การกระทำ | ระบบทำอะไร |
|---|---|---|---|
| 1 | ผู้ใช้ | โปรไฟล์ → "ที่อยู่ของฉัน" → "เพิ่มที่อยู่" | — |
| 2 | ผู้ใช้ | กรอก ชื่อผู้รับ, เบอร์, ที่อยู่, จังหวัด, รหัสไปรษณีย์ (+ ติ๊กตั้งเป็นหลัก) | validate: ทุกช่องบังคับ, รหัสไปรษณีย์ 5 หลัก |
| 3 | ระบบ | บันทึก | insert `addresses`; ถ้า is_default → update แถวอื่นของ user เป็น false ก่อน |

## Main Flow D: ลืมรหัสผ่าน (เพิ่ม 2026-08-22)

| # | ผู้กระทำ | การกระทำ | ระบบทำอะไร |
|---|---|---|---|
| 1 | ผู้ใช้ | หน้าเข้าสู่ระบบ → กด "ลืมรหัสผ่าน?" | ไป `(auth)/forgot-password` |
| 2 | ผู้ใช้ | กรอกอีเมลที่ใช้สมัคร → กด "ส่งลิงก์ตั้งรหัสผ่านใหม่" | `POST /auth/forgot-password` |
| 3 | ระบบ | ปิดตั๋วเก่าที่ยังใช้ได้ + ออกตั๋วใหม่ (ทรานแซกชันเดียว) แล้วส่งอีเมล | update `password_reset_tokens` set `used_at` where `used_at is null` → insert แถวใหม่ (sha256 · หมดอายุ 30 นาที) → ส่งเมล **แบบไม่รอผล** |
| 4 | ระบบ | ตอบ **204 เสมอ** ไม่ว่าอีเมลจะมีในระบบหรือไม่ | หน้าจอขึ้น "ถ้ามีบัญชีที่ผูกกับ … เราส่งลิงก์ไปให้แล้ว" — ข้อความเดียวกันทั้งสองกรณี |
| 5 | ผู้ใช้ | เปิดลิงก์ในอีเมล | `(auth)/reset-password?token=…` |
| 6 | ผู้ใช้ | กรอกรหัสใหม่ + ยืนยัน → กด "บันทึกรหัสผ่านใหม่" | `POST /auth/reset-password` |
| 7 | ระบบ | ปิดตั๋ว + เปลี่ยนรหัส + **เพิกถอน refresh token ทุกใบ** (ทรานแซกชันเดียว) | update ตั๋ว (`used_at is null` อยู่ใน where) → update `users.password_hash` → update `refresh_tokens` set `revoked_reason='password_reset'` |
| 8 | ระบบ | พาไปหน้าเข้าสู่ระบบ **ไม่ล็อกอินให้อัตโนมัติ** | ทุก session เพิ่งถูกตัดไป การเด้งเข้าแอปเลยจะกลบข้อเท็จจริงนั้น |

## Alternate / Error Flows

- **E1 อีเมลซ้ำ (Flow A ขั้น 3):** API ตอบ 409 (unique ที่ DB เป็นด่านจริง) → แสดง "อีเมลนี้ถูกใช้แล้ว — เข้าสู่ระบบแทน?" พร้อมลิงก์ไปหน้า login
- **E2 รหัสผ่านผิด (Flow B ขั้น 1):** แสดง "อีเมลหรือรหัสผ่านไม่ถูกต้อง" (ไม่บอกว่าผิดอันไหน)
- **E3 ลิงก์รีเซ็ตใช้ไม่ได้ (Flow D ขั้น 6):** ไม่มีจริง / ใช้ไปแล้ว / หมดอายุ / ถูกแทนที่เพราะขอใบใหม่ → **400 `INVALID_RESET_TOKEN` ข้อความเดียวกันทั้งหมด** ("ลิงก์ตั้งรหัสผ่านใหม่นี้ใช้ไม่ได้แล้ว กรุณาขอลิงก์ใหม่อีกครั้ง") — แยกเมื่อไหร่คือการยืนยันว่าตั๋วใบนั้นเคยมีจริง
- **E4 เปิดหน้า reset โดยไม่มี `?token=` (ลิงก์ถูกตัดตอนคัดลอก):** แสดงหน้า "ลิงก์ไม่สมบูรณ์" + ปุ่มขอลิงก์ใหม่ ไม่ใช่จอขาว
- **E5 ขอลิงก์ถี่เกินไป (Flow D ขั้น 2):** 429 หลังครั้งที่ 3 ใน 5 นาที (ต่อ IP) — เพดานนี้เข้มกว่า `/auth/*` ตัวอื่นเพราะ endpoint นี้สั่งให้ระบบส่งเมลออกไปหาคนอื่น
- **A1 ล็อกเอาท์:** โปรไฟล์ → ออกจากระบบ → `POST /auth/logout` (เพิกถอน refresh token ใบนั้นด้วย `revoked_reason='logout'`) → กลับ `(auth)/login`

## Postcondition
- มี `auth.users` + `profiles` ผูกกัน, session ถูกจำไว้ในเครื่อง, มีที่อยู่อย่างน้อย 1 รายการ (จำเป็นก่อน [W04](w04-subscribe-checkout.md))
