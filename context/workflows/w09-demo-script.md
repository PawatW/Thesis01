# W09 — สคริปต์เดโม่ต่อกรรมการ (พร้อม time-travel)

> Actor: ทีม thesis | ใช้ทุก feature | เป้าหมาย: โชว์ครบ core loop ใน ~10 นาที โดยไม่ต้องรอข้ามวันจริง

## เตรียมก่อนเดโม่ (seed)

- `anan-api/prisma/seed.ts` (`npm run db:seed`): หมวดครบ 10 หมวด, ร้านตัวอย่าง 3 ร้าน, สินค้า 12 ชิ้นพร้อมแผนหลาย cycle, บัญชีสาธิต 5 บัญชี:
  - `buyer.demo@anan.app` — มีที่อยู่ + บัตร demo + subscription เดิม 2-3 รายการ (จะได้มีประวัติให้ดู)
  - `seller.demo@anan.app` — เจ้าของร้านกาแฟ มี subscriber อยู่แล้ว
- บัญชี `admin.demo@anan.local` (ตั้ง is_admin ใน seed) — หน้า `(admin)/engine`: ปุ่ม **Run engine** + ช่องใส่ **run_date จำลอง** (time-travel) · คืนข้อมูลเดโม่ด้วย `cd anan-api && npm run db:seed` ก่อนซ้อมรอบใหม่

## ลำดับเดโม่ 10 นาที

| นาที | โชว์อะไร | ขั้นตอน | จุดที่ต้องชี้ให้กรรมการเห็น |
|---|---|---|---|
| 0-1 | ปัญหา + คอนเซปต์ | สไลด์สั้น | fragmentation ของ subscription commerce |
| 1-3 | **ฝั่งผู้ซื้อ: หา + เทียบ** ([W03](w03-browse-compare.md)) | เปิดหมวดกาแฟ → เทียบ 3 แบรนด์ | ราคาต่อหน่วยเทียบข้ามขนาดได้ + % ส่วนลด subscribe |
| 3-5 | **Subscribe** ([W04](w04-subscribe-checkout.md)) | checkout จนจบ | ป้าย DEMO payment + ข้อความ "ยกเลิกได้ทุกเมื่อ" + ออเดอร์รอบแรกเกิดทันที |
| 5-7 | **Time-travel รอบอัตโนมัติ** ([W06](w06-recurring-cycle.md)) | `(admin)/engine` ใส่วันที่ +1 เดือน → Run → กลับหน้าแอพ | ออเดอร์รอบ 2 โผล่ + แจ้งเตือน + **กด Run ซ้ำ → ไม่มีออเดอร์ซ้ำ (โชว์ idempotency!)** |
| 7-8 | **ความยืดหยุ่น** ([W05](w05-manage-subscription.md)) | skip 1 รายการ, pause 1 รายการ → time-travel อีกรอบ → Run | รายการที่ skip/pause ไม่เกิดออเดอร์ — จุดขายเรื่องความไว้ใจ |
| 8-10 | **ฝั่งร้านค้า** ([W08](w08-seller-orders.md)) | สลับบัญชี seller → อัปเดตสถานะส่งของ → เปิด forecast | มือถืออีกเครื่องรับ notification สด + forecast ช่วยวางแผนสต๊อก + MRR |
| (สำรอง 1 นาที ถ้ามีเวลา) | **เมื่อไม่ราบรื่น** ([W11](w11-order-exception.md)) | ร้านกดยกเลิก 1 ออเดอร์ → กลับฝั่ง buyer | คืนเงินจำลองทันทีในทรานแซกชันเดียว + รอบถัดไปยังอยู่ครบ — ตอบคำถาม "ถ้าของหมดล่ะ" ก่อนกรรมการถาม |

## จุดเสี่ยงตอนเดโม่ + แผนสำรอง

- **เน็ตมหาลัยช้า / เครื่องมีปัญหา:** ระบบรันบนเครื่องทั้งหมด (API + DB) จึงไม่ต้องพึ่งเน็ต — แต่ยังควรอัดวิดีโอ backup ทุก flow ไว้ล่วงหน้า 1 ชุด
- **time-travel แล้วข้อมูลเละ:** มีสคริปต์ `reset-demo.sql` ล้าง orders/notifications ที่เกิดจากเดโม่ กลับสู่สภาพ seed ได้ใน 1 คำสั่ง
- **ลืมลำดับ:** พิมพ์ตารางข้างบนพกไว้

## คำถามที่กรรมการน่าจะถาม (เตรียมคำตอบ)

1. "ต่างจาก Shopee ยังไง" → recurring relationship + ยืดหยุ่น (skip/pause) + เทียบราคาต่อหน่วยข้ามแบรนด์ + forecast ฝั่งร้าน
2. "ทำไมไม่ตัดเงินจริง" → scope เป็น demo โดยตั้งใจ, ออกแบบ `PaymentProvider` interface เผื่อเสียบ gateway จริง (ชี้โค้ด + future work ในเล่ม)
3. "ถ้า cron ไม่รันล่ะ" → เงื่อนไข `<=` เก็บตก + `engine_runs` log ตรวจย้อน (ชี้ [W06](w06-recurring-cycle.md) E2)
4. "วัดความสำเร็จยังไง" → churn จาก `subscription_events`, MRR ฝั่งร้าน, อัตรายืนยันรับของ, คะแนนรีวิว × churn
5. "ถ้าร้านส่งไม่ได้ / ของไม่ถึงล่ะ" → [W11](w11-order-exception.md): ร้านยกเลิกรอบนั้น + คืนเงินจำลองในทรานแซกชันเดียว หรือผู้ซื้อแจ้งปัญหาเข้าคิว admin — และชี้ว่า `delivered` ที่ร้านกดเอง ต่างจาก `confirmed_at` ที่มีแต่ผู้ซื้อตั้งได้
6. "รู้ได้ไงว่าร้านไหนดี" → รีวิวจากผู้ที่ subscribe จริง พร้อมป้าย "รับมาแล้ว N รอบ" ([W12](w12-review.md)) — ข้อมูลที่แพลตฟอร์มซื้อครั้งเดียวให้ไม่ได้
