## 0. ทำไมถึงรื้อ (2026-08-19)

ชุดเดิมยกมาจาก mockup marketplace "NovaShop" ทั้งดุ้น — violet `#8B5CF6` + gradient ม่วง→ชมพู + การ์ดขาวลอยบนพื้น `#F3F3F7` ปัญหาที่วัดได้จากหน้าจอจริงก่อนรื้อ:

| สิ่งที่วัด | ค่าที่ได้ | ผล |
|---|---|---|
| ค่า `box-shadow` ที่ต่างกันทั้งหน้า | **1 ค่า** | ทุกพื้นผิวลอยเท่ากันหมด สายตาไม่มีที่ลง เกิดการ์ดลอยซ้อนการ์ดลอย |
| contrast ของอักษรแทนรูปในการ์ดสินค้า | **1.11 : 1** | มองไม่เห็นเลย ช่อง 120px เป็นสี่เหลี่ยมเทาเปล่า |
| contrast ของ `textFaint` `#A1A1AA` บนขาว | **2.56 : 1** | ตก WCAG AA ทั้งที่แบก "ราคาซื้อครั้งเดียว" ซึ่งเป็นจุดขาย |
| ตัวอักษรที่ใหญ่ที่สุดในแอป | **22px** บนจอ 1440px | ไม่มีอะไรนำสายตา |
| คอลัมน์กริดที่ได้จริง | **3 จาก 4** | สูตรคิดจากความกว้างหน้าต่าง แต่กริดอยู่ใน ScrollView ที่กันรางสกรอลล์ 15px |

เชิงเนื้อหา: palette เดิมเกือบทั้งชุดเป็น Tailwind default (violet-500, zinc-900…100, amber-500, emerald-500) — **ไม่มีสีไหนอธิบายได้ว่าทำไมต้องเป็นสีนี้กับกาแฟ ยาสีฟัน อาหารแมว** และม่วงในตลาดไทยอ่านว่า "แอปการเงิน" ไม่ใช่ "ของใช้เข้าบ้าน"

## 1. ทิศทางใหม่ — "ชั้นของใช้ในบ้าน + จังหวะของรอบ"

ยืนบนสองอย่างที่กลุ่มเป้าหมายเห็นทุกวัน ไม่ใช่ template SaaS:

1. **ชั้นวางของในร้านชำ** → เขียวสน + เหลืองดาวเรืองบนพื้นกระดาษอุ่น · เขียว+เหลืองคือชุดสีค้าปลีกที่คนไทยอ่านออกโดยไม่ต้องเรียน (ร้านสะดวกซื้อ ร้านชำ แพ็กเกจสมุนไพร)
2. **ฉลากสินค้า** → สีประจำหมวด (`categoryTones`) ที่ทำหน้าที่แทนรูปสินค้าได้จริง

**หลักที่ถือ:** ANAN ขาย *เวลา* ไม่ใช่ *ราคา* — สิ่งที่ marketplace ซื้อครั้งเดียวให้ไม่ได้คือ "ของจะมาอีกเมื่อไหร่" ลำดับสายตาบนทุกหน้าจึงต้องให้เวลามาก่อนเงิน

## 2. ตัวอักษร

**คง `IBM Plex Sans Thai` เป็นฟอนต์เดียวของระบบ** — ชั้น display ใช้ Bold ตัวเดิมดันขนาดขึ้นแทนการลงฟอนต์ใหม่

> เหตุผล: ทุก Playwright spec รอ `#splash` หายก่อนเริ่ม assert ถ้าฟอนต์ใหม่โหลดพลาดจะแดงพร้อมกันทั้ง 84 เคส ผลตอบแทนไม่คุ้มความเสี่ยงในเฟสนี้

| role | ขนาด/บรรทัด | ใช้ที่ |
|---|---|---|
| `display` | 40/46 tabular | ตัวเลขนับถอยหลังบนการ์ด "ถัดไป" |
| `h1` | 28/38 | |
| `h2` | 22/32 | |
| `h3` | 18/28 | หัวข้อ section |
| `h4` | 16/26 | นับถอยหลังในรายการ |
| `body` | **16/26** (เดิม 14/22) | กลุ่มเป้าหมายคือคนซื้อของใช้เข้าบ้าน ไม่ใช่ผู้ใช้แอปสาย tech |
| `small` | 14/22 | |
| `caption` | 13/20 | |
| `label` | **12/17** (เดิม 11/16) | status pill — 11px ภาษาไทยเล็กเกินขีดอ่านออก |

**กฎภาษาไทย 2 ข้อ:**
- line-height ทุกตัว **≥1.55** ให้สระบน (ิ ี ึ ื ั ็) กับวรรณยุกต์ที่ซ้อนสองชั้นหายใจได้
- **ห้ามใส่ `letterSpacing` กับข้อความที่มีอักษรไทย** — สระบนกับวรรณยุกต์ผูกตำแหน่งกับฐาน การถ่างช่องไฟทำให้ลอยหลุด (ใส่ได้เฉพาะละตินล้วน เช่น `ANAN`, `DEMO`)
- ตัวเลขเงิน/วันใช้ `fontVariant: ['tabular-nums']` ไม่งั้นนับถอยหลังแล้วกระตุก

## 3. ความลึก — เส้นมาก่อนเงา

```
flat/card  → borderWidth 1 + borderColor line   (พื้นผิวส่วนใหญ่)
floating   → 0 12px 32px rgba(28,25,23,.16)     (Modal, ถาดเทียบ — จอละไม่เกิน 1 ชิ้น)
```

`radius`: `xs 4 · sm 6 · md 10 · lg 14 · xl 18 · xxl 24 · pill 999`

**`pill` สงวนไว้ให้ status badge กับชิปหมวดเท่านั้น** — ปุ่ม action ใช้ `md`
เมื่อปุ่มเป็น pill ด้วย สายตาแยกไม่ออกว่าอันไหนกดได้ อันไหนคือสถานะ (ปัญหาจริงบนหน้า subscriptions ที่มีทั้งสองอย่างในการ์ดใบเดียว)

## 4. ปุ่มของรายการ — 4 ระดับน้ำหนัก

`subscriptions.tsx` มี 6 ปุ่มต่อรายการ เดิมน้ำหนักเท่ากันหมด ตอนนี้:

| ปุ่ม | น้ำหนัก |
|---|---|
| ข้ามรอบ · กลับมาใช้งาน | `primary` — เขียวทึบ |
| เลื่อน 7 วัน · หยุดชั่วคราว | `outline` — ขาวมีขอบ |
| เปลี่ยนรอบส่ง · เปลี่ยนที่อยู่ · รีวิว | `quiet` — ไม่มีขอบ ตัวหนังสือเขียว |
| ยกเลิก | `danger` — text link สี clay |

> **DOM เหมือนเดิมทุกประการ** ปุ่มครบ 6 ตัว จำนวนคลิกเท่าเดิม — ทางที่ไม่เลือกคือยุบเข้าเมนู "⋯" ซึ่งจะทำให้ `#subs-action-*` หายจาก DOM จนกว่าเมนูจะกาง แต่ e2e เรียกตรงทั้ง 8 ตัว

## 5. Layout & responsive

| ขนาดจอ | โครง |
|---|---|
| **≥1200px** | sidebar 240 + เนื้อหา (+ rail 340 บนหน้าแรก) · ซ่อน bottom tab bar |
| **768–1199px** | คอลัมน์เดียว + แถบบนบอกโหมด + bottom tabs · เนื้อหากว้างสุด 1120 |
| **<768px** | คอลัมน์เดียว + แถบบนบอกโหมด + bottom tabs · กริดสินค้า 2 คอลัมน์ |

> คอนโซลผู้ดูแลใช้ 768 เป็นจุดตัด (web-first) ไม่ใช่ 1200 และไม่มี bottom tabs — จอแคบจึงได้แถบนำทางแนวนอนใต้หัวจอแทน (`ConsoleNavRow`)

`contentMaxWidth` = **1120** (เดิม 1440 ซึ่งทำให้เว็บเป็นมือถือยืด)

**กริดสินค้าคำนวณจากค่าคงที่ของ layout ทั้งหมด** — `useProductGrid({ rail, inCard })` หักตามลำดับ: sidebar (ถ้าจอ ≥1200) → รางสกรอลล์ (**วัดจริง** ไม่ใช่เดาจากความกว้าง) → padding ของ `Screen` → `contentMaxWidth` (ครอบหลัง padding · ปลดเฉพาะหน้าที่ส่ง `<Screen wide>`) → rail (เฉพาะหน้าที่มี) → padding + **เส้นขอบ 1px สองด้าน** ของ `Card` (เฉพาะกริดที่อยู่ใน `Card`) → เผื่อเศษ sub-pixel อีก 2px

| หน้า | `rail` | `inCard` |
|---|---|---|
| หน้าแรก | ✓ | ✓ |
| หน้าหมวด · หน้าร้าน | – | – (กริดเป็นลูกของ `Screen` ตรง ๆ) |

> **ห้ามเปลี่ยนไปใช้ `onLayout`** — ลองแล้วมันไม่ยิงเลยบน react-native-web 0.21 ชุดนี้ (ใส่ `console.log` ในคอลแบ็กแล้วไม่มีอะไรออกมาแม้แต่ครั้งเดียว) · สูตรคงที่ตรวจสอบได้ด้วยการคูณเลข
>
> **ความกว้างหน้าต่างต้องมาจาก `useWindowWidth()` เท่านั้น** ไม่ใช่ `useWindowDimensions()` ของ react-native ซึ่งค้างที่ค่าตอน mount บนชุดนี้ (ดู `src/lib/useWindowWidth.ts`)
>
> **สูตรต้องประมาณพื้นที่แบบ "ขาด" เสมอ** — คิดเกินจริงแม้แต่ 1px การ์ดใบสุดท้ายจะตกบรรทัดแล้วเสียที่ทั้งช่อง ส่วนคิดขาดแค่ทำให้การ์ดแคบลงใบละไม่กี่พิกเซล
>
> **รางสกรอลล์เดาจากความกว้างหน้าต่างไม่ได้** — ของเดิมนับว่ามีรางเฉพาะจอ ≥768 แต่หน้าต่างเดสก์ท็อปที่ลากให้แคบกว่านั้นยังมีรางกินที่ 15px อยู่ · ตอนนี้วัดด้วย probe element ครั้งเดียวแล้วจำไว้ (คืน 0 เองบนสกรอลล์บาร์แบบลอยทับและบน native)

## 5.1 คอนโซลตามบทบาท (role shells)

บัญชีเดียวสวมได้หลายหมวก จึงต้องตอบให้ได้ในสายตาเดียวว่า "ตอนนี้อยู่โหมดไหน" —
คำตอบคือ**พื้นของแถบนำทาง** ไม่ใช่ตัวหนังสือ (ของเดิมทั้งสามโหมดพื้นขาวเหมือนกันหมด
ต่างแค่ข้อความในเมนู ผลคือล็อกอินด้วยบัญชีร้านแล้วอ่านไม่ออกว่าไม่ใช่หน้าผู้ซื้อ)

| โหมด | พื้นแถบนำทาง | ความหมาย | ตัวตนบนหัว |
|---|---|---|---|
| ผู้ซื้อ | `white` บนพื้นกระดาษ | หน้าร้าน เดินดูของ | `ANAN` + ชื่อผู้ใช้ (หรือ "โหมดผู้ซื้อ" ถ้ามีหลายบทบาท) |
| ร้านค้า | `pineDeep` (เขียวสนเข้ม) | หลังร้าน ที่ทำงาน | **ชื่อร้านจริง** + โลโก้ร้าน |
| ผู้ดูแล | `ink` (ดำหมึก) | ห้องเครื่องของระบบ | `ANAN` + "โหมดผู้ดูแลระบบ" |

- โทเคนอยู่ที่ `roleShells` ใน `theme.ts` — **ไม่มีสีใหม่เข้าระบบ** ทุกค่ามาจาก palette เดิม
- `accent` (marigold) ใช้กับไอคอนของเมนูที่เลือกอยู่และ badge ตัวเลขที่ยังไม่อ่านเท่านั้น
- ท้ายแถบนำทางของทุกโหมดมี **ตัวสลับโหมด + ออกจากระบบ** เสมอ — ตัวสลับแสดงเฉพาะโหมดที่บัญชีนั้นมีจริง (`rolesOf`) และเป็น UX ล้วน (endpoint ตรวจ role จาก token เองทุกครั้ง)
- หน้าแรกหลังล็อกอินมาจาก `landingHref()` ที่เดียว: ผู้ดูแล → `(admin)` · เจ้าของร้าน → `(seller)` · ที่เหลือ → `(buyer)`

## 6. สิ่งที่คงไว้จากของเดิม (ผ่านแล้ว ไม่ต้องแตะ)

- `shadow()` helper ที่แยก 3 platform — วิธีคิดถูก แค่ใช้ให้น้อยลง
- `statusTones` เป็นคู่ bg/fg และ**แยก "ร้านถูกระงับ" (ส้ม) ออกจาก "หยุดเอง" (เหลือง)**
- ข้อความยืนยันก่อนทำทุกอัน — บอกผลลัพธ์ก่อนเกิดจริง (และ e2e ล็อกข้อความไว้)
- แยก "โหลดไม่สำเร็จ" ออกจาก "ไม่มีรายการ"
- `minHeight: 44` ทุก touch target
- `DemoBadge` ติดทุกจุดที่มีตัวเลขเงิน (กฎเหล็กข้อ 1) — เปลี่ยนเป็น**ตราประทับขอบประ** ไม่ใช่ป้ายสีทึบ เพื่อไม่ให้กินช่องสีที่สงวนไว้ให้สถานะกับเวลา · **ข้อความคงเดิมทุกตัวอักษร**

## 7. ข้อจำกัดของ React Native ที่ต้องรู้

| `Link asChild` | **style ของลูกต้องเป็นอ็อบเจกต์ก้อนเดียว** — array → จอขาว · **ฟังก์ชัน `({pressed}) => …` → สไตล์ถูกทิ้งทั้งก้อนแบบเงียบ ๆ** (เมนู sidebar เคยเป็นไอคอนซ้อนตัวอักษรอยู่นาน เพราะแบบนี้) → ใช้ `StyleSheet.flatten([...])` เสมอ |

## 8. Component กลาง

`Card` (`raised`/`plain`) · `Button` (primary/secondary/ghost/danger) · `Pill` (+`dot`) · `DemoBadge` · `EmptyState` · `ErrorNote` · `SectionHeader` · `Screen` (+`wide`) · `Splash` · `ProductCard` · `CycleRail` · `TextField` · `CompareTrayBar`

**เปลือกคอนโซล** (`src/components/console/`) — `ConsoleShell` (ประกอบทั้งหมด รับ `role`/`brand`/`items`/`wide`) · `ConsoleNav` (sidebar) · `ConsoleNavRow` (แถบแนวนอนของจอแคบที่ไม่มี bottom tabs) · `ConsoleTopBar` · `ModeSwitcher` + `SignOutButton` — แทน `SideNav` เดิมทั้งหมด

**`ProductImage` / `Avatar`** (`src/components/Media.tsx`) คือทางเดียวที่แสดงรูปในแอป — ใช้ `expo-image` และมีทางสำรองสองชั้น: ลิงก์เสีย (`onError`) → ไอคอนหมวด · ไม่มีลิงก์ → ไอคอนหมวด · รับเฉพาะ `https://` เพราะ `<Image>` ที่ได้ uri ใช้ไม่ได้จะขึ้นกล่องว่างเงียบ ๆ แทนที่จะ error

**`CycleRail`** คือ signature element: แถบแสดงว่าตอนนี้อยู่ตรงไหนระหว่างรอบที่แล้วกับรอบหน้า ใช้ `<View>` ล้วน ไม่มี dependency ใหม่ · หยุดชั่วคราว → แถบเทาค้าง · ข้ามรอบ → แถบกระโดดถอย ผู้ใช้เห็นผลของปุ่มที่เพิ่งกดโดยไม่ต้องอ่าน toast
